# BASIC MAPP（Basic Minimal AI Project Protocol）

**版本：** 2.0

**目的：** 为 AI 长期参与软件研发提供极简、稳定、可持续的多 Agent 协作协议。

---

# 1. 使命

让 AI 完成任务所需读取的信息最少。

任何规则必须服务于这个目标；如果一条规则增加的复杂度大于价值，就应删除。

---

# 2. 三个真相来源

- 代码是真相来源（Source of Truth）。
- Git 是历史来源（Source of History）。
- BASIC MAPP 是上下文来源（Source of Context）。

不重复记录已经存在于其他位置的信息。

---

# 3. 三个核心问题

Agent 进入项目时只需回答三个问题：

| 问题 | 读取 | 回答 |
|---|---|---|
| 这是什么项目？ | `PROJECT.md` | 目标、边界、长期原则 |
| 为什么这样设计？ | `DECISIONS.md`（按需） | 影响当前工作的关键决策 |
| 现在该继续做什么？ | `ACTIVE.md` | 当前工作、阶段、下一步、阻塞 |

除特殊情况外，Agent 不应读取其他项目文档。

---

# 4. 核心文件

| 文件 | 内容 | 质量标准 |
|---|---|---|
| `PROJECT.md` | 项目稳定上下文 | 30 秒内理解 |
| `ACTIVE.md` | 当前工作上下文 | 10 秒内理解 |
| `DECISIONS.md` | 长期决策索引 | 5 分钟内理解关键决策 |

超过标准则压缩，不通过新增文档解决复杂度。

---

# 5. 工作协议

1. 理解项目背景（`PROJECT.md`）。
2. 理解当前状态（`ACTIVE.md`）。
3. 按需读取 `DECISIONS.md`。
4. 获取完成任务所需的最小上下文。
5. 在职责范围内执行，优先复用，不扩大范围。
6. 验证输出：可被下一 Agent 继续使用。
7. 产生影响项目状态的信息时更新 `ACTIVE.md` / `DECISIONS.md`。
8. 只记录最终决策、原因、影响，不记录讨论与过程。

---

# 6. 信息记录原则

只记录未来仍影响工作的信息；Git 已保存的信息不重复记录。

---

# 7. 行为原则

先理解，再行动；只读取所需信息；优先复用；保持简洁；不扩大任务范围；代码与文档冲突时以代码为准并及时修正文档。

---

# 8. 元规则

新增规则前先问：这解决的是长期存在的问题，还是特殊情况？特殊情况不加入本协议。

---

# 9. 最终原则

BASIC MAPP 不是文档系统、知识库或项目管理工具，而是一套轻量级 AI 多 Agent 协作协议：让 Agent 用最少上下文理解项目、在明确职责内工作、输出可继续使用的结果、让项目更易维护。

---

# 10. 合规清单

每次任务完成前确认：

- 最小上下文：只读取了完成任务所需信息。
- 先理解后行动：充分理解目标后才工作。
- 最小修改：改动控制在必要范围。
- 职责边界：只处理职责范围内的事。
- 有价值的记录：只记录未来有价值的信息。
- 项目变得更好：项目比开始时更易理解、维护。
