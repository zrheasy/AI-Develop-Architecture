# PROJECT.md Standard

**Version:** 1.0

---

# 1. Purpose

PROJECT.md 用于定义整个项目的稳定上下文。

它回答：

> 这是一个什么项目？

目标：

让任何 Agent 在最短时间内理解：

- 项目存在的目的。
- 项目的长期目标。
- 项目的边界。
- 项目的核心原则。

---

# 2. Core Principle

PROJECT.md 只保存长期稳定的信息。

应该记录：

- 项目目标。
- 产品方向。
- 核心范围。
- 长期约束。
- 技术背景。

不应该记录：

- 当前任务。
- 开发进度。
- 临时问题。
- 历史过程。
- 决策讨论。

---

# 3. Standard Structure


# Project Name


## Overview

一句话描述项目。


## Mission

项目长期使命。

回答：

为什么存在？


## Product Vision

产品希望提供什么长期价值。


## Scope


### In Scope

项目负责的能力范围。


### Out of Scope

项目明确不负责的范围。


## Core Principles

项目长期遵循的原则。

例如：

- 产品能力优先。
- 最小复杂度。
- 用户价值驱动。


## Technology Context

技术背景。

只描述：

- 技术栈。
- 平台。
- 系统组成。


不描述：

- 实现细节。
- 当前开发任务。


## Project Structure

项目主要结构说明。


## Current Phase

当前项目阶段。

例如：

- MVP
- Growth
- Maintenance

---

# 4. Content Rules


## Rule 1

保持稳定。

PROJECT.md 不应该频繁修改。


## Rule 2

保持简洁。

目标：

Agent 30 秒内理解项目。


## Rule 3

避免重复。

已有信息：

- Feature
- Decision
- Task

不复制到 PROJECT.md。


---

# 5. Update Criteria

只有以下情况更新：

- 项目目标变化。
- 产品方向变化。
- 项目边界变化。
- 长期原则变化。

普通需求：

不更新 PROJECT.md。


---

# 6. Quality Checklist


□ 是否描述整个项目，而不是当前工作？

□ 是否未来半年仍然有效？

□ 是否删除了临时信息？

□ Agent 是否可以快速理解项目？
