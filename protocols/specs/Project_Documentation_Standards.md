# PROJECT.md Standard

**版本：** 2.1

## 1. 作用

`PROJECT.md` 记录项目稳定上下文，帮助 Agent 快速理解项目目标、边界和与自身工作相关的长期信息。

项目中存在两种 `PROJECT.md`：

| 文件 | 维护者 | 作用 |
|---|---|---|
| 根目录 `PROJECT.md` | PM Agent | 项目级完整上下文，记录整个项目的目标、产品、范围和整体工程背景 |
| `Agents/{Agent}/PROJECT.md` | 对应 Agent | 职责域上下文，记录与该 Agent 工作相关的资料 |

根目录 `PROJECT.md` 是项目级真相来源。Agent 工作空间中的 `PROJECT.md` 从根目录派生，但不是全文复制；领域版可以补充本职责域的稳定信息，不能与根目录的项目目标、边界和长期原则冲突。

## 2. 根目录 PROJECT.md（PM 版）

PM 版记录完整的项目级信息，但不记录任务过程、开发日志或具体实现细节。

### 标准结构

```markdown
# Project Name

## Overview
一句话描述项目及其主要形态。

## Mission
项目长期使命：为什么存在。

## Product Vision
产品希望为用户提供的长期价值。

## Scope
### In Scope
项目负责的范围。

### Out of Scope
明确不负责的范围。

## Core Principles
项目长期产品、工程或协作原则。

## Product Context
核心用户、主要场景和产品边界。

## Current Phase
MVP / Growth / Maintenance 等。
```

### 内容边界

PM 版可以包含所有影响项目协作的稳定项目级信息，但应遵守：

- 只记录跨职责域或影响整个项目的信息；
- 产品细节沉淀到 Product Requirement / Feature；
- 长期决策的结论、原因和影响沉淀到 `DECISIONS.md`；
- 当前状态、进行中的任务和阻塞沉淀到 `ACTIVE.md`；
- 具体实现、接口细节和代码结构以代码及对应 Agent 文档为准。

## 3. Agent PROJECT.md（领域版）

领域版只保留该 Agent 所需的项目上下文，不要求包含完整项目资料。

所有领域版至少包含：

```markdown
# Project Name — {Agent} Context

## Project Context
与本职责域相关的项目背景。

```

根据 Agent 类型补充以下内容：

| Agent 类型 | 领域版重点内容 |
|---|---|
| Product | 用户、场景、产品目标、产品边界和产品规划背景 |
| UI | 设计方向、设计系统、交互原则和设计资产边界 |
| Frontend | 前端架构、应用边界、关键技术选型、工程约束和与其他模块的集成边界 |
| Backend | 后端架构、服务边界、数据与接口层次、关键技术选型、工程约束和外部依赖 |
| Mobile | 移动端架构、平台边界、关键技术选型、工程约束和与后端/前端的集成边界 |
| QA | 质量目标、测试策略、测试环境、自动化能力和验收边界 |

领域版的架构和技术选型记录当前有效状态；选型原因、权衡、替代方案和跨领域影响记录在该 Agent 的 `DECISIONS.md`，需要项目级确认的决策再由 PM 纳入根目录 `DECISIONS.md`。

## 4. 继承与同步

初始化 Agent 工作空间时：

1. Agent 读取根目录 `PROJECT.md`；
2. 提取与自身职责相关的稳定信息；
3. 创建领域版 `PROJECT.md`；
4. 按职责补充领域上下文，开发 Agent 同时补充架构和关键技术选型；
5. 发现项目目标、范围或长期原则不明确或冲突时，反馈 PM，不自行改写项目级内容。

根目录发生项目级变化时，PM 通知受影响 Agent 更新领域版。领域版新增的领域信息如影响其他 Agent 或项目目标，必须升级 PM 评估，不能单方面覆盖根目录内容。

## 5. 记录与更新规则

只记录未来仍会影响工作的稳定信息：

- 目标、方向、范围和长期原则；
- 当前有效的产品或工程背景；
- 稳定的架构、技术选型和集成边界；
- 影响长期工作的约束。

不记录：

- 当前任务、实时进度、阻塞和待办；
- 讨论过程、临时想法和开发日志；
- 已由代码、Git、Feature、Task 或 Decision 保存的信息。

仅在对应稳定信息发生变化时更新。普通需求、单个 Task 或临时问题不更新 `PROJECT.md`。

## 6. 质量标准

- **准确：** 与项目当前有效事实一致；
- **相关：** 领域版只保留对应 Agent 需要的信息；
- **稳定：** 不因单个任务频繁修改；
- **简洁：** PM 版应在 30 秒内让 Agent 理解项目，领域版应在 20 秒内让对应 Agent 理解其工作背景。
